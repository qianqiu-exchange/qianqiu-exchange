# 千秋交易所 · 风起未定 V0.3

历史只决定开局，你是一股能投资、囤货、经营与支援的势力。买卖人物股、粮草、军械、战马和营地经营份额；把物资交给一个或多个势力，改变补给、战局和下一季价格。

这是静态网页游戏，可直接打开，也可部署GitHub Pages；不需要后端、账号或必需的API。所有金币只在游戏内使用。

## 开始玩

1. 完整解压后双击 `index.html`，保留目录结构。
2. 「街谈」里找人聊生意、路途或住客。人物说的是局部见闻和传言，不是历史预测问答；没有先选合约、相信/不相信或可信度评分。
3. 「盘面」里买入、加仓、减仓或清仓。报价、持仓平均成本、含费净回收与已实现盈亏来自真实账本。
4. 「物资支援」里安排交付，可以分给多个势力，不要求持有人物股；收盘前可以取消，库存与原成本会归还。
5. 观察沈砚与其他交易商后，继续调整仓位或分配。开盘最多3笔，全季成功交易总计5笔；剩余额度带入回应阶段。可以一直观望。
6. 推进本季，实际交付生效，世界按军力、补给、士气、机动与种子演化，再重估市场。八季后展示现金与持仓估值，估值不直接兑付进钱包。

首版人物为曹操、刘备、孙权、诸葛亮；势力为北方、刘备一方与江东，诸葛亮资产与刘备势力的组织后勤相关。开局参考207年局势，属性和数量为游戏化设定，之后不是固定历史回放。

## 资产怎样进入对局

| 标的 | 买入后是什么 | 投入支援后 |
|---|---|---|
| 人物股 | 对相关势力前景的游戏资产 | 不自动资助，也不能当物资交付 |
| 粮草仓单 | 每份代表一批库存 | 消耗库存，补给+3、士气+0.6；交付补偿按确认时中间价的30%估计 |
| 军械仓单 | 每份代表一批库存 | 消耗库存，军力+2；补偿按确认时中间价的20%估计 |
| 战马仓单 | 每份代表一批库存 | 消耗库存，机动+2、军力+0.7；补偿按确认时中间价的20%估计 |
| 营地经营份额 | 可买卖的经营份额 | 锁定两次季末结算，每次补给+2、士气+0.7；每份每季经营费0.45金币，到期归还份额和原成本 |

属性均受0—100上限约束。营地与交付补偿从目标势力金库支付，金库不足则少付，不保证抵回买入成本。最后一季会提前归还尚未到期营地，不追加未经营季节的费用。资源消耗、锁定、可用库存与市场库存分别记账。

人物价值根据各方当前军力、补给、地盘、士气与影响力重估；物资价格受整体短缺、军备需求和天气影响；实际交易也产生供需价格冲击。这是可调试的规则原型，不是经济学或历史准确性承诺。

## 预设与BYOK

不配置模型也能玩完整八季。每季最多串门两段，每段三轮；回应阶段只查看记录。预设回复按角色已知的风声和话题生成，可能过时或听错。真实模型只负责角色表达与沈砚的一笔受限交易决定，不写世界结算结果、不运行返回代码。

「连接模型」提供独立的两套配置：

- **TokenPay**：按官方S256 PKCE无回调模式发起授权；到TokenDance确认额度/有效期，复制一次性Code回来交换专用Key。会话验证器只在内存，刷新需重新发起。可读取实时模型目录，只显示支持 `openai:chat-completions` 的模型；也可填已有Key。TokenPay推理请求带稳定 `X-App-URL`。
- **自有API / Agent配置**：手动填写完整Chat Completions地址、模型与Key；或把游戏里的指令和 `AGENT_SETUP.md`、`agent-setup.json` 交给有权限的Agent，导入不含Key的公开配置，再在页面填入授权Key。导入配置或修改接口会清除旧Key，防止旧凭据被带到新端点。无需TokenPay账号。服务商必须允许浏览器CORS；Agent不能凭空获得额度或绕过服务端跨域限制。

实际模型调用只在主动聊天、观察对手、测试连接时发生。最多每季6次闲谈加1次沈砚判断，测试另计。取消不提交游戏动作，但服务商可能已处理并计费；失败使用预设内容，不会切换另一来源余额。沈砚最多1笔、8份、买入最多80金币，无空头或借贷。

连接配置和凭据可分别选择在此浏览器记忆；默认Key仅驻留内存。记住配置后才可选择记住Key；清除配置会同时清除该来源已记住的Key。恢复配置不代表连通，刷新不会自动启用付费调用。此记忆不是加密保险箱，同源脚本或浏览器环境仍可能读取。游戏存档、公开连接导出、源码均不包含Key；授权Code与PKCE验证器不持久化。

TokenPay协议来源：

- https://tokendance.space/docs/api-key-oauth.md
- https://tokendance.space/docs/app-attribution.md
- https://tokendance.space/llms.txt

授权、目录、推理与归因均已用模拟接口测试；未用真实账号完成登录、扣费或合作后台对账。此版使用复制Code回游戏的官方流程，没有自动回跳页面。

## 存档与旧版

架空世界使用独立的 `qianqiu-sandbox-world-v1` 本地存档及 `HX_WORLD_SAVE` JSON格式，旧版IndexedDB/localStorage不覆盖。旧版 `HX_SAVE` 不能无损变为此经济模型，导入会明确拒绝。

从规则面板打开 `classic.html` 继续旧版史实回放与共创工坊，旧源码、剧本与测试保留；旧版说明见 `README_CLASSIC.md`。不要把旧页面中的史实结果或合约规则当成新玩法机制。

自动保存失败时使用下载JSON备份。每季只有主动推进才演化，无后台监听、遥测或账号同步。公开仓库不含玩家本地存档。

## 静态发布

将完整目录作为GitHub Pages发布目录。运行入口与CSS、JS、授权模块、说明使用相对地址，支持组织下仓库子路径，含 `.nojekyll`。无需运行Node或Python。正式部署后应使用稳定App URL，并实际验证目标来源的CORS、授权交换和模型调用。

如未来以商业服务或分润作为主要用途，还需核对托管平台适用规则；官网、网页和测试 APK 按用户授权发布；没有创建 TokenPay 合作应用或承诺分润收益。

## 开发与验收

核心测试需要Node.js 18+，不需要安装依赖：

```powershell
node --test tests/engine.test.cjs tests/tavern.test.cjs tests/world.test.cjs tests/connections.test.cjs
```

实际65项全部通过，输出见 `test-results.txt`。涵盖旧版回归、架空资产守恒、支援改变同种子战局、成本和营地期限、模型受限订单、凭据配置、PKCE与归因。

浏览器验收使用Playwright（开发用，Node.js 20+）：

```powershell
npm install --no-save playwright
npx playwright install chromium
node tests/world-browser-smoke.cjs
node tests/connection-ui-smoke.cjs
```

已有浏览器可设 `HX_BROWSER_EXECUTABLE` 为其路径，`HX_TEST_OUTPUT` 指定截图/结果目录，默认系统临时目录。测试使用临时浏览器配置和模拟外部接口，不触碰真实玩家存档，不需要API Key。实际主流程17项、连接专项2项，共19项通过，结果见 `docs/world-browser-results.json`。

所有模拟检查均不等同真人测试、真实手机键盘或无障碍合格；平衡性、长期重玩价值、实际模型延迟和真实TokenPay账户需继续试玩与联调。
